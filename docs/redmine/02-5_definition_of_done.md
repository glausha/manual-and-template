# Section 2.5: 完了の定義 (Definition of Done) チェックリスト

本ドキュメントは、自動運転システム（ADS）開発プロジェクトにおける「完了の定義（DoD）」チェックリストを定義する。
チケットを「完了」ステータスに遷移させる前に、該当するチェックリストをすべて満たしていることを確認すること。

---

## 1. 実装タスクのDoD

開発者が実装タスクを完了する際に確認するチェックリスト。

### 1.1 コード品質

- [ ] GitLabのMRがマージされていること
- [ ] 単体テストがパスしていること（カバレッジ80%以上）
- [ ] 静的解析（Linter）のエラーがないこと
- [ ] コンパイル警告がゼロであること
- [ ] コーディング規約に準拠していること

### 1.2 レビュー

- [ ] コードレビューが完了していること（レビュー担当者の承認あり）
- [ ] レビュー指摘事項がすべて対応済みであること
- [ ] レビューコメントへの返信が完了していること

### 1.3 ドキュメント

- [ ] 必要に応じてAPIドキュメントが更新されていること
- [ ] コード内のコメントが適切に記載されていること
- [ ] 変更履歴がコミットメッセージに適切に記録されていること

### 1.4 テスト

- [ ] 新規追加した機能のテストケースが作成されていること
- [ ] 回帰テストがパスしていること
- [ ] CI/CDパイプラインが正常終了していること

---

## 2. バグ修正のDoD

バグ修正タスクを完了する際に確認するチェックリスト。

### 2.1 修正確認

- [ ] 再現手順で現象が発生しないことを確認したか
- [ ] 他の機能への影響（回帰）がないか確認したか
- [ ] 類似箇所に同様の問題がないか確認したか

### 2.2 品質記録

- [ ] 「混入工程」カスタムフィールドが設定されていること
- [ ] 「根本原因」カスタムフィールドが設定されていること
- [ ] 修正内容と原因がチケットのコメントに記録されていること

### 2.3 レビュー・テスト

- [ ] コードレビューが完了していること
- [ ] 修正に対する単体テストが追加されていること
- [ ] QAチームによる確認テストがパスしていること

### 2.4 再発防止

- [ ] 必要に応じて再発防止策が検討されていること
- [ ] 横展開が必要な場合、関連チケットが起票されていること

---

## 3. 成果物（Deliverable）のDoD

設計書・仕様書などの成果物を完了する際に確認するチェックリスト。

### 3.1 内容確認

- [ ] 上長またはアーキテクトの承認ログがあるか
- [ ] テンプレートに準拠した形式で作成されているか
- [ ] 図表・ダイアグラムが適切に含まれているか

### 3.2 品質確認

- [ ] 誤字脱字チェックが完了しているか
- [ ] 用語の統一が取れているか
- [ ] バージョン番号・更新日が正しく記載されているか

### 3.3 格納・共有

- [ ] GitLabの `/docs` ディレクトリに格納されているか
- [ ] 関連するRedmineチケットにリンクが記載されているか
- [ ] 99_Libraryへの登録が完了しているか（承認済みの場合）

---

## 4. ストーリーのDoD

ストーリー（Lv2）を完了する際に確認するチェックリスト。

### 4.1 タスク完了

- [ ] 配下のすべてのタスクが「完了」ステータスであること
- [ ] 発生したバグがすべて解決済みであること

### 4.2 受入基準

- [ ] プロダクトオーナーまたはステークホルダーの受入確認が完了していること
- [ ] 受入基準（Acceptance Criteria）がすべて満たされていること

### 4.3 デモ・検証

- [ ] スプリントレビューでのデモが完了していること
- [ ] フィードバックへの対応が完了していること

---

## 5. エピックのDoD

エピック（Lv1）を完了する際に確認するチェックリスト。

### 5.1 ストーリー完了

- [ ] 配下のすべてのストーリーが「完了」ステータスであること
- [ ] 当初スコープがすべて実装されていること

### 5.2 品質確認

- [ ] システムテストがパスしていること
- [ ] 性能要件を満たしていること
- [ ] セキュリティ要件を満たしていること

### 5.3 リリース準備

- [ ] リリースノートが作成されていること
- [ ] 関連ドキュメントが最新化されていること
- [ ] 99_Libraryに成果物が格納されていること

---

## 6. ASIL対応のDoD（追加チェック）

ASILレベルがA以上の機能に対する追加チェックリスト。

### 6.1 ASIL A/B

- [ ] FMEA（故障モード影響分析）が実施されていること
- [ ] 安全分析レポートがレビューされていること

### 6.2 ASIL C/D（上記に加えて）

- [ ] FTA（故障の木解析）が実施されていること
- [ ] 独立した検証チームによるレビューが完了していること
- [ ] セーフティケースが更新されていること
- [ ] ハザード分析との整合性が確認されていること

---

## 7. Wikiサイドバー用チェックリスト（コンパクト版）

RedmineのWikiサイドバーに埋め込むためのコンパクト版チェックリスト。

```markdown
## ✅ 完了の定義（DoD）

### 実装タスク
- [ ] MRマージ済み
- [ ] 単体テストパス
- [ ] Linterエラーなし
- [ ] コードレビュー承認

### バグ修正
- [ ] 再現しないことを確認
- [ ] 回帰影響なし
- [ ] 混入工程/根本原因を記録

### 成果物
- [ ] 承認ログあり
- [ ] 99_Libraryに格納

📖 詳細: [[完了の定義チェックリスト]]
```

---

## 8. チェックリスト運用ルール

### 8.1 適用タイミング

| ステータス遷移 | チェックリスト |
|---------------|----------------|
| 進行中 → レビュー中 | 該当DoDの「コード品質」「テスト」を確認 |
| レビュー中 → 完了 | 該当DoDの全項目を確認 |

### 8.2 確認方法

1. チケットのコメント欄にチェックリストをコピーする
2. 各項目を確認しながらチェックを入れる
3. すべてチェック完了後にステータスを「完了」に変更する
4. レビュー担当者がチェック内容を確認し、承認する

### 8.3 例外対応

- DoD項目が適用外の場合は、理由をコメントに記載し、「N/A」と記録する
- 緊急対応でDoD項目を省略する場合は、マネージャーの承認を得て、後日対応チケットを起票する

```markdown
- [ ] 単体テストがパス（カバレッジ: __%)
```

```markdown
- [ ] 単体テスト追加済み
- [ ] QA確認テストパス

確認者: @___

```
